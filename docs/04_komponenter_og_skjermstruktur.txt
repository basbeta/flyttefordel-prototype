# 04 — Komponenter og skjermstruktur

Prosjekt: Fordelsklubben / Flyttefordel MVP
Dokumenttype: PRD-del 04
Tema: Komponenter og skjermstruktur
Plattform: Mobil PWA for Android og iPhone


## 1. Generelt

Dette dokumentet beskriver skjermene og komponentene som trengs for app og admin. Det er skrevet implementasjonsvennlig slik at Claude Code kan bruke det til å bygge komponenter, routes og UI-struktur.

Appen skal bygges mobil først. Ikke bruk tid på desktop- eller nettbrettoptimalisering for sluttbrukerappen.

Admin kan være desktoporientert, fordi den brukes internt.

## 4. App layout

### 4.1 MobileShell

Wrapper for hele mobilappen.

Ansvar:

- Setter mobil maks-/min-bredde
- Håndterer safe-area på iPhone
- Inneholder bunnnavigasjon
- Håndterer global loading/error
- Håndterer PWA install prompt/instruksjon

Props:

- children
- activeTab
- showBottomNav


### 4.2 BottomNavigation

Fast bunnnavigasjon.

Elementer:

- Hjem
- Fordeler
- Nær deg
- Mine
- Profil

Krav:

- Store trykkflater
- Tydelig aktiv state
- Må ta hensyn til iOS safe-area
- Ikke mer enn fem valg


### 4.3 TopBar

Enkel toppseksjon.

Varianter:

- Standard med logo/navn
- Back button på detaljsider
- Tittelvariant
- Eventuelt profil/innstillinger-ikon


## 5. Hjemskjerm

Komponenter:

- HomeScreen
- HeroCarousel
- HeroCard
- SegmentGreeting
- FeaturedBenefitsSection
- CategoryShortcutGrid
- TimeLimitedBenefitsSection
- NearbyPreviewSection
- EmptyFallbackSection

### 5.1 HomeScreen

Ansvar:

- Henter aktive heroer basert på segment og geografi
- Henter utvalgte fordeler
- Henter kategorier
- Henter eventuelle lokale fordeler
- Viser fallback hvis ingen spesifikke treff

### 5.2 HeroCarousel

Krav:

- Kan vise 1–5 heroer
- Støtter bilde, tittel, undertittel og CTA
- Må ikke være for høy på små skjermer
- Skal kunne vise fallback-hero

HeroCard-felter:

- imageUrl
- title
- description
- ctaLabel
- ctaTargetType
- ctaTargetValue
- advertiserLogo optional
- badge optional

### 5.3 SegmentGreeting

Eksempeltekster:

- Nylig flyttet: «Gjør det litt enklere å komme på plass.»
- Flyttet tidligere: «Fordeler for hjemmet, hverdagen og alt imellom.»
- Ikke flyttet: «Gode fordeler samlet på ett sted.»
- Ukjent: «Finn fordeler som passer deg.»

## 8. Redemption-komponenter

### 8.1 CodeRedemption

Elementer:

- Knapp: «Vis kode»
- Kodeboks etter reveal
- Kopier-knapp
- Lenke til annonsør, hvis finnes
- Instruksjonstekst

States:

- hidden
- revealed
- copied
- expired


### 8.2 UniqueCodeRedemption

Elementer:

- Knapp: «Hent kode»
- Loading state mens kode tildeles
- Kodeboks
- Feil ved tom kodepool

Må kalle API som atomisk tildeler kode.


### 8.3 QRRedemption

Elementer:

- Knapp: «Vis QR-kode»
- QR-modal eller inline QR
- Instruksjon: «Vis denne i butikk»
- Utløpsinfo


### 8.4 ExternalLinkRedemption

Elementer:

- Primær CTA
- Ekstern lenke-indikator
- Eventuell info om at man forlater appen


### 8.5 LeadFormRedemption

Elementer:

- Felter definert av admin
- Samtykketekst
- Send-knapp
- Kvittering

MVP-felter som må støttes:

- Navn
- E-post
- Telefon
- Postnummer
- Fritekst
- Checkbox samtykke


## 9. Nær deg-skjerm

Komponenter:

- NearbyScreen
- PostcodePrompt
- NearbyBenefitList
- LocationSummary
- ChangeLocationButton
- NearbyEmptyState

Flow:

1. Hvis postnummer finnes: vis lokale fordeler
2. Hvis ikke: vis prompt
3. Hvis ingen lokale fordeler: vis nasjonale fordeler og hyggelig tomtilstand

Ikke bygg kart som avhengighet i MVP.

## 22. Tilgjengelighet

MVP skal minst støtte:

- Semantiske knapper og lenker
- Label på inputfelter
- God kontrast
- Fokusmarkering
- Alt-tekst på bilder der relevant
- Ikke bare farge for status
- Store nok trykkflater


## 23. Responsivitet

Sluttbrukerapp:

- Optimaliseres for mobilbredder ca. 320–430 px
- Ikke bruk energi på desktop/tablet
- Desktop kan vise enkel container eller melding

Admin:

- Kan være desktop-first
- Må fungere godt for intern drift
