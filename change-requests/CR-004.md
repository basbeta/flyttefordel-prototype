# CR-004: Fase 4 — Admin-grensesnitt

Status: Approved
Created: 2026-05-22

## Business Goal

Admin-staben skal kunne opprette, publisere og administrere fordeler, annonsører og heroer uten utviklerbistand. Leder ser nøkkeltall på dashboardet og kan eksportere leads.

## Proposed Solution

Implementer fullt admin-backoffice bak JWT-beskyttet innlogging:

1. **Auth** — innloggingsside, JWT-cookie, middleware-beskyttelse av alle `/admin/**`-ruter
2. **Dashboard** — 5 statistikkort (aktive, planlagte, utløper snart, nye leads, kodepool-advarsel)
3. **Fordeler** — liste med statusfilter + opprett + rediger + status-toggle (publiser/pause/arkiver)
4. **Annonsører** — liste + opprett + rediger
5. **Heroer** — liste + opprett + rediger
6. **Leads** — skrivebeskyttet liste med filtrering + CSV-eksport
7. **Koder** — vis kodepooler per fordel + legg til koder via paste

**Demo-auth:** credentials mot `ADMIN_EMAIL`/`ADMIN_PASSWORD` env vars (dokumenteres som demo-only).

## Impact Analysis

### Affected Components

| Komponent | Endring |
|---|---|
| `src/middleware.ts` | JWT-sjekk for `/admin/**` (unntatt `/admin/login`) |
| `src/lib/admin/auth.ts` | Nytt — JWT-signering, verifisering, requireAdminAuth() |
| `src/lib/queries/adminQueries.ts` | Nytt — alle admin-spørringer |
| `src/app/admin/login/` | Nytt — innloggingsside |
| `src/app/admin/page.tsx` | Dashboard med ekte stats |
| `src/app/admin/benefits/` | Liste + opprett + rediger |
| `src/app/admin/advertisers/` | Liste + opprett + rediger |
| `src/app/admin/heroes/` | Liste + opprett + rediger |
| `src/app/admin/leads/` | Liste + CSV-eksport |
| `src/app/admin/codes/` | Liste + legg til koder |
| `src/app/api/admin/**` | Auth-beskyttede CRUD-ruter |

### Database Impact
Ingen schema-endring. Alle nødvendige tabeller finnes fra CR-001.

### Security Impact
- JWT valideres i middleware + i hvert API-endepunkt (defence in depth)
- `admin_token` cookie: `httpOnly`, `sameSite=lax`, 8 timers utløp
- Admin-API returnerer 401 uten gyldig token
- `internalNotes` og `formData` eksponeres aldri til consumer-app

## Acceptance Criteria
- [ ] Uautentiserte besøk på `/admin/**` redirectes til `/admin/login`
- [ ] Innlogging med riktig e-post + passord setter JWT-cookie og sender til dashboard
- [ ] Dashboard viser ekte tall fra DB
- [ ] Admin kan opprette en fordel og publisere den — fordelen dukker opp i consumer-appen
- [ ] Admin kan pause og arkivere en fordel
- [ ] Admin kan opprette og redigere annonsører
- [ ] Admin kan se alle leads, filtrere og laste ned CSV
- [ ] TypeScript kompilerer rent
