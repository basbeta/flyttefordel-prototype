# CR-003: Fase 3 — Anonyme sesjoner, lagrede fordeler og brukerprofil

Status: Done
Created: 2026-05-22

## Business Goal

Gi brukere verdi uten tung registrering — de skal kunne lagre fordeler, oppgi postnummer og segment og se lokalt tilpasset innhold på tvers av besøk, uten å måtte logge inn.

## Problem Statement

`isSaved` er hardkodet `false` på alle fordeler. `/saved`, `/nearby` og `/profile` returnerer 404. Appen har ingen kontekst om hvem brukeren er, og viser alle fordeler til alle uten targeting. Brukerne kan ikke ta vare på noe mellom besøkene.

## Proposed Solution

Implementer anonym sesjonsidentitet via cookie (`anonymousId`) og en tilhørende `UserSession`-rad i databasen. Bygg på dette:

1. **Anonym sesjon** — `lib/session/` lager/henter `anonymousId`-cookie. Middleware oppretter `UserSession`-rad ved første besøk.
2. **Lagrede fordeler** — save/unsave via API, knyttet til `sessionId`. Hjerte-knapp vises på **både `BenefitCard` (liste) og detaljside**. Vises samlet under `/saved`.
3. **Brukerprofil** — `/profile`-side der bruker kan sette postnummer og flyttestatus. Lagres på `UserSession`.
4. **Nær deg** — `/nearby`-side filtrerer fordeler på postnummer (krever FR-030-032). Viser nasjonale fordeler om ingen treff.
5. **Placeholder-sider ferdigstilt** — `/nearby`, `/saved`, `/profile` erstattes med ekte implementasjoner.

**Utenfor scope for denne fasen:**
- Targeting-logikk (`lib/targeting/`) — utsatt til CR-004
- Supabase Auth (e-postinnlogging) — krever `NEXT_PUBLIC_ANON_KEY` som er placeholder

**Supabase Auth (e-postinnlogging) er utenfor scope for denne fasen.** Det krever `NEXT_PUBLIC_ANON_KEY` og `SUPABASE_SERVICE_ROLE_KEY` fra Supabase-dashboardet. Persistering på tvers av enheter er not-a-demo-requirement.

### Database Impact

Ingen skjemaendring. Eksisterende modeller (`UserSession`, `SavedBenefit`) brukes:
- `UserSession`: `anonymousId`, `postcode`, `movingStatus`, `lastSeenAt`  
  **OBS:** `UserSession` mangler `postcode` og `movingStatus`-felt — trenger migrasjon.
- `SavedBenefit`: lagres med `sessionId`, `userId = null`

Ny migrasjon: legg `postcode` og `moving_status` på `user_sessions`.

### API Impact

Nye endepunkter:
- `POST /api/benefits/[slug]/save` — lagre fordel (returnerer 201)
- `DELETE /api/benefits/[slug]/save` — avlagre fordel (returnerer 204)
- `PATCH /api/session/profile` — oppdater postnummer + segment

### UX Impact

- `BenefitCard` og `BenefitDetail`: hjerteikonet bytter tilstand ved save/unsave
- `/saved`: tom tilstand («Du har ingen lagrede fordeler ennå»)
- `/nearby`: tom tilstand uten postnummer («Legg inn postnummer for å se lokale fordeler»)
- `/profile`: skjema med postnummer-input og segment-velger
- Alle three sider er lenket fra `BottomNavigation`

### Security Impact

- `anonymousId` er en tilfeldig UUID — ikke personidentifiserende
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` i produksjon
- Postnummer er ikke persondata — kan lagres i klartekst
- `UserSession` inneholder ikke navn, e-post eller telefon i denne fasen

### Performance Impact

- Middleware leser/skriver `UserSession` på hvert sidebesøk — bruk upsert med `lastSeenAt`
- `getBenefitBySlug` og `getActiveBenefits` får ekstra join for `isSaved` — ubetydelig for demo
- Targeting utsatt til CR-004 — ingen ekstra kostnad i denne fasen

## Rollback Strategy

Alle nye API-ruter er additive. Fjern middleware og nye ruter. Sett `isSaved` tilbake til `false`. DB-rader i `user_sessions` og `saved_benefits` er ufarlige å la stå.

## Migration Strategy

Legg til to nye kolonner på `user_sessions`:
```sql
ALTER TABLE user_sessions ADD COLUMN postcode VARCHAR(4);
ALTER TABLE user_sessions ADD COLUMN moving_status user_moving_status;
```
Prisma-migrasjon genereres med `npx prisma migrate dev`.

## Risks

| Risiko | Sannsynlighet | Konsekvens | Tiltak |
|---|---|---|---|
| `UserSession`-duplikat ved race condition (SSR + middleware) | Lav | Lav | Bruk `upsert` på `anonymousId` |

| Demo-database pauser (Supabase free tier) — session-oppretting feiler | Middels | Lav | Graceful fallback: app virker uten DB-sesjon |
